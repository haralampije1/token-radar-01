# Contributing to token-radar-01

This repository is a make.fun bounty entry (token-radar-01): a pre-token token
launch radar built by an AI coding agent for the "Build the best token launch
radar" bounty ($1,325 USDC, 10 paid places, program/v1 judged dashboard).

## How the entry is built

`main.ts` is the entrypoint. It:

1. Reads the sealed DefiLlama snapshot from `/input/snapshot.json` (758
   protocols, 40 on the watchlist) via `--input`, or defaults to `/input`.
2. Scores every pre-token protocol with the radar-3 model in `lib/model.ts`
   (implied value from TVL, 7-day growth and listing age).
3. Runs the gate's own seven validity rules (`boardIssue`) and aborts before
   writing anything if the board would be rejected (missing watchlist slugs,
   ranks not 1..N, implied value rising with rank, all-equal values, bad farm
   steps, non-positive implied value).
4. Writes `/output/board.json`, `/output/data.js`, copies `dashboard/` and
   `screenshots/`, and writes `/output/dossier.json` via the vendored
   `vendor/makefun-board.ts`.

Run locally (outside the grader container):

```sh
mkdir -p out
MAKEFUN_OUTPUT_DIR=out node main.ts --input path/to/snapshot.json
```

No network, no API keys, no external configuration. Same snapshot always
produces byte-identical outputs.

## What to change

- The scoring model lives in `lib/model.ts` (`MODEL` constants,
  `impliedValue`, `buildBoard`, `farmSteps`). Every formula input comes from
  the snapshot; no protocol name is special-cased.
- The dashboard (`dashboard/`) reads `window.RADAR` from `data.js` and makes
  no network requests.
- The provenance docs (`docs/METHODOLOGY.md`, `docs/DESIGN.md`,
  `docs/LIMITATIONS.md`, `docs/FAQ.md`) explain intent, choices and limits and
  were written by the same agent sessions that wrote the code.

## What not to change

- `board.json`, `data.js`, `dossier.json` and the screenshots are build
  outputs; do not hand-edit them. They are regenerated by running `main.ts`.
- `vendor/makefun-board.ts` is vendored byte-for-byte from the token-radar-01
  kit; changing it would break the scorer's byte comparison of
  `dossier.json`.
- `.makefun/owner.json` names the payout wallet and must stay.
- The repo's About/topics and README make.fun badges are required by the
  bounty's repository checks.

## Provenance requirement (make.fun check thinking_reproduces)

For the make.fun entry, the bundled agent sessions must show this code being
written (at least 30% of counted lines traced to the sessions). Every edit to
`main.ts`, `lib/model.ts`, `dashboard/app.js` or these docs therefore goes
through the agent's in-session tooling, and the sessions are bundled with the
entry via `makefun bundle` before submission.
